The game is a static Canvas 2D client. There is no VoL API, database binding, bot token, reward integration or shared economy. The current campaign uses `brotd-infinity:campaign:v2`; the older `kings-guard:toon:formation:v1` save is preserved separately; the public hostname, Telegram's WebView and ordinary browsers have separate storage. Closing/reloading an unfinished wave returns to preparation with the latest saved formation and earned resources; the active fight is not persisted. Army edits save immediately.

The permanent **Army** dock below the battlefield shows a compact 5 × 3 formation grid without the king or castle, with the Slave Market and Barracks underneath. One slave produces a separate reserve fighter with a personal level; fighters cannot be purchased or upgraded for gold. An empty tile opens reserve deployment; an occupied tile offers replacement, Move and To barracks. Locked tiles are purchased with gold, starting at 25 and increasing per tile. Each Barracks card now offers Recruit: choose a fighter, then an army tile. Empty tiles deploy it; occupied tiles return their old fighter to the Barracks. Locked tiles require the existing gold unlock before placing the selected recruit. Selection and cancellation spend nothing. An individual reserve fighter can be sold for one gold from its detail view. The last owned fighter is protected. Fresh empty accounts receive three starting slaves once. Every edit saves immediately and affects the next wave snapshot; ongoing combat and automatic wave countdowns continue. Existing personal levels, army and unlocked tiles are preserved. A fresh empty army starts after conversion, deployment and Start. Settings and Buildings leave play running; Auto waves On/Off remains available.

`telegram.mjs` wraps the official SDK. It detects an actual Telegram launch, publishes viewport/inset CSS variables, calls ready/expand, applies the game's header colors where supported, and watches both document visibility and Telegram activation. Backgrounding freezes combat, the automatic-wave countdown and capture cooldown; they resume automatically on return. The Treasury and a built Slave Market accumulate up to four hours of offline income per absence and credit it automatically on active return, saving both currencies, partial progress and their consumed timestamps together. Old saves begin Treasury absence tracking on their first active visit after the update; the market starts unbuilt and produces only after its 100-gold purchase, at one slave per 30 real minutes. Closing confirmation is enabled while a battle is running. Unsupported Telegram APIs do not prevent ordinary browser play.

## Publish the static preview

The existing Cloudflare Pages project is `tg-game` (`tg-game-23f.pages.dev`), whose production branch is `main`. The dedicated `bro-infinity` preview branch hosts only this game's built files at its root. Run deployment from the prototype directory so the repository's unrelated root `functions/` is not bundled.

From the worktree root:

```powershell
node ../../node_modules/vite/bin/vite.js build king-defense-toon --config king-defense-toon/vite.config.mjs
```

From `king-defense-toon/`:

```powershell
node ../../../node_modules/wrangler/bin/wrangler.js pages deploy ../public/king-defense-toon --project-name tg-game --branch bro-infinity --commit-dirty=true
```

The deployment must be Preview, never Production. Inspect Wrangler's returned branch alias and verify it before configuring BotFather. HTML is revalidated; hashed assets use immutable caching. Keep using that branch alias for future updates so the local save origin remains stable. The normal production website and other Mini Apps are not replaced by this preview deployment.
